Render the rows you have, then place QueryStatus beside them. It distinguishes missing information, failed acquisition, revalidation, and a proven-empty result.

<ComponentPreview name="query-status" />

<Example package="ui" file="query-status.tsx" region="example" />

Customize `empty` and `loading` for the screen. An issue offers the result's retry when acquisition is idle. Retry acquires unsuccessful information; it is not a refresh policy.

QueryStatus does not turn unresolved filter candidates into matches or fill in absent fields. Your row rendering still chooses how to show missing selected values. See [partial results](/docs/data/build/partial-results).
