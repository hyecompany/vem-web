## Behavior and choices

Mount Toaster once around the part of your application that produces notifications. `toast.add({ title, description, type })` uses the shared manager; `createToastManager()` provides an isolated manager, as in this example. `useToastManager()` reads the nearest provider.

Use `type` for `success`, `error`, `warning`, `info`, or `loading` feedback. Set `timeout: 0` when a message must stay until dismissed. Use the returned ID with `update` or `close`. Put required decisions and detailed errors near the affected content rather than relying on a transient toast.

For a custom presentation, compose ToastProvider, ToastPortal, ToastViewport, Toast, ToastContent, ToastTitle, ToastDescription, ToastAction, and ToastClose. [ActivityToasts](/docs/ui/components/activity-toasts) connects this presentation to Vem Data’s shared feedback ownership.
