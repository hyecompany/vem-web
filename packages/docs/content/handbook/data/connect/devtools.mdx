Use **live inspection** to understand what a mounted screen requests. Use **scenarios** to see how that same screen handles missing data, denied access, or a failed command. Feature components use their usual queries, commands, and editors in either mode.

## Mount the inspector

Vem UI's `DataInspector` shows discovered queries, commands, editors, and activities. Put it in your existing developer-tools surface, such as TanStack Devtools:

<Example package="ui" file="devtools.tsx" region="panel" />

The panel accepts an existing inspector; it does not create or close clients or request data. The optional `header` prop holds application-specific connection information or mode controls. Both stylesheets are required.

For live inspection, wrap the application's client with `inspectClient`:

<Example package="ui" file="devtools.tsx" region="prepare" />

Pass the returned `client` to `DataProvider` and `panel` to your developer-tools host. Only consumers using the wrapper appear in the inspection. The host calls `dispose()` when retiring this development session; it detaches inspection without closing the real client. Closing the visible panel alone need not retire the session.

The inspector shows consumer demand and results, not owner-side source comparisons. See [how Vem chooses reads](/docs/data/connect/planning#choose-using-available-evidence) for the selection policy; service or network observations identify the actual reads.

Pass `scenario.client` to the application's `DataProvider`. Give that same scenario to the panel as both its inspection and its controls:

<Example package="ui" file="devtools.tsx" region="scenario-panel" />

Open a screen to discover its consumers. The panel can then change query states and sample values, command admission and outcomes, or editor permissions. Commands run against an isolated runtime, not your server. Call `scenario.close()` when disposing that session; recreate it for a full reset.

A partial query with a missing display field keeps its matching row visible. A missing filter field leaves an unresolved candidate. These controls exercise feature behavior; they do not simulate worker ownership, persistence, or real network traffic.

## Keep the integration in development

Load the module containing the inspector **and its styles** through a build-time development branch. For Vite:

<Example package="ui" file="devtools-host.tsx" region="development" />

The `devtools.js` module is the panel and preparation code above. Other build tools should use their equivalent compile-time development constant. Keep imports of inspection, scenarios, the panel, and its stylesheet inside that development module graph.

Verify the final **client and worker** bundles exclude development imports and initialization; hiding the panel is not sufficient. Vem Data's `/devtools` entry also exposes `subscribe` and `getSnapshot` if your host needs a custom inspector view.
