## Render a list and filter

In an application that already uses Vem, import its resource contract (`tasks` here). The application supplies `DataProvider` once; each screen just uses the hooks. If you are connecting a new application, start with [define a resource](/docs/data/connect/resources).

<Example file="feature-guide/list.tsx" region="list" />

`openOnly` is ordinary UI state. Changing it changes the query description. Vem reuses known task statuses to answer immediately; a missing field can require a read. Inline descriptions do not need `useMemo`, a cache key, or an effect.

`ReadStatus` is a small shared component, shown on the [partial-results page](/docs/data/build/partial-results#render-a-useful-status). It explains loading, errors, or incomplete results while leaving known rows visible. `row.key` is the stable React key; `row.data` contains plain selected values.
