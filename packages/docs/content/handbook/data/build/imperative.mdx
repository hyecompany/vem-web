Use the application's existing `DataClient` in a controller or another UI framework. It describes the same information as a React hook; it does not create another owner.

## Read once

<Example file="feature-guide/imperative.ts" region="read" />

The read settles with available, partial, or failed information after the acquisition attempt. A missing title remains `undefined`; inspect `issues` rather than assuming a complete object. `exists === false` is established absence.

Pass an `AbortSignal` when the caller needs a deadline or can leave the screen. Aborting, closing the client, or using an invalid description can reject the promise; handle those errors at your caller boundary. There is no automatic deadline for an unresponsive source.

The returned outcome has the same success, partial, failure, and uncertainty meanings as [React actions](/docs/data/build/actions). The action handle also provides `subscribe` and `getSnapshot` for progress. Unsubscribing stops observation, not execution.

Retry is on the query handle. You do not need a separate refresh query or an event subscription in the view.

Pass `{ acquire: false }` as the second argument to `client.watch` to observe permitted knowledge without requesting missing or stale data. The handle still receives changes and access withdrawal; its explicit `retry()` can acquire.

## Observe read progress without requesting data

<Example file="feature-guide/imperative.ts" region="read-status" />

`watchReadStatus` reports related work from current consumers, including other tabs. Its snapshot has `pending`, `revalidating`, `issues`, and `canRetry`; `handle.retry()` retries unsuccessful matching work. It creates no data demand, and disposing it stops observation without stopping other consumers' reads. See [related read status](/docs/data/build/display#show-progress-for-related-reads) for matching and retry behavior.

<details>
<summary>Writing an editor without React</summary>

`prepareEdit` returns the writable values, matching ETag, and disclosure information. `saveEdit` accepts that prepared representation and the draft. A custom editor must manage the access lifetime of copied values, preserve the original baseline while dirty, and discard it on authority or owner changes. The React `useEdit` binding already supplies that state management; the lower-level pair is not a drop-in form binding.
